# 宿舍补给站 MVP

面向大学宿舍场景的学生零食小店微信小程序。学生通过商家分享卡片直达店铺，或搜索商家告知的店铺名称；线上提交订单，商品送达后双方线下付款。

## 已实现功能

### 学生端

- 按店铺名称搜索
- 分享卡片直达指定店铺
- 浏览分类、商品、价格和实时库存
- 购物车与起送金额校验
- 填写联系人、手机号、送达位置和备注
- 提交无需在线支付的订单
- 查看订单状态、取消待接单订单、确认收货

### 商家端

- 创建和编辑店铺
- 设置店名、公告、营业时间、起送金额及配送费
- 商品分类、价格、库存、上下架管理
- 开始营业/打烊
- 接单、拒单、开始配送、确认送达及完成订单
- 今日订单、成交额、待接单和低库存数据
- 分享店铺卡片给同学

2. 编译并进入“找店”页。
3. 搜索“阿豪”或直接点击演示店铺。
4. 可在“我的 → 我要开店”体验完整商家流程。
5. “我的 → 重置本机体验数据”可恢复初始状态。

1. 当前项目已配置云环境 `smooth-kiwi-d3gjwm74v84784b65`。
2. `miniprogram/app.js` 中保持 `useCloud=true`，超级管理员可按下节从管理页切到原云函数，仅对本机本次运行生效。原云函数账号尚无管理员权限时，由维护者先在原云数据库授权。

#### 数据库准备

- 不使用数据库保存当前后端模式，不需要新增配置表、配置接口或执行切换 SQL。此前全局配置表脚本及相关实现已移除；没有操作实际数据库。若维护者已经自行建过该表，本版不会读取或自动删除它。
- Java 原业务表仍须准备好。已有 `platform_users` 的有效 `SUPER_ADMIN` 不用重复插入；只有新环境缺少首位管理员时才按 Java README 人工授权。两套数据库的角色独立维护。
- `system_dictionaries` / `system_collection_schemas` 中文说明可在 Java 会话通过“数据库中文说明”主动同步；这不建表或迁移业务数据。
- `notification_templates` 缺记录时需人工初始化后再配置模板。店铺、商品、订单、库存及其他角色如需沿用，要另行安排迁移。
- MySQL 连接参数、`WECHAT_APPID` 属于部署配置；云环境、服务名和默认后端保存在小程序代码中。不要为本机切换重复执行 V1 或打开自动初始化。

使用已部署的 Java 业务服务即可测试本机切换，无需新增后端控制服务。发布、部署和业务数据操作仍由维护者确认，本次没有执行。

#### 超级管理员切换规则

- 入口：“我的 → 平台管理后台 → 本机后端测试”，仅当前后端的超级管理员可见。切换时重新检查当前身份，并检查目标后端中同一 OpenID 的超级管理员权限，避免切过去后无法切回；不会自动复制或授予权限。
- 点击“确认切换”后检查目标初始化、身份和通知配置，成功才更新本机内存并重建管理页。按钮和“本次运行后端”显示当前设备实际使用的通道。
- 仅影响本机本次运行，不影响其他用户；切后台返回或页面刷新保留选择，下一次 `App.onLaunch` 冷启动恢复默认 Java。后端选择不存入本地缓存或数据库。
- 启动顺序为初始化微信云能力 → 检查链接来源 → 初始化 Java 业务后端 → 加载可选通知配置。普通业务及图片上传等待启动完成；Java 通知配置失败按停用处理，不阻断业务启动。
- 有在途请求时不允许切换；检查期间阻止重复切换及新的普通业务请求。目标连接、权限等检查失败不切换；页面重载失败恢复原本机后端，业务请求不跨库重发。
- 默认 Java 不可用时明确提示启动失败，不自动回退原云函数或演示数据。已切到云函数的会话只访问云函数，不需要额外访问 Java 读取模式。
- 原 `globalData.env` 继续用于云函数和商品图片云存储，不能改成云托管环境；MySQL 只存云文件 ID。
- 云托管业务请求使用 `wx.cloud.callContainer` 和 `X-WX-SERVICE`，不由客户端发送身份头。错误保留 SDK `errMsg` 和错误码；不自动重试业务写请求，不回退到云函数或本地数据。无需用 `wx.request` 或公网域名代替。
- 可先只读验证微信链路。在微信开发者工具 Console 执行：
  ```js
  wx.cloud.callContainer({
    config: { env: 'prod-d0gs4er2552d66779' },
    path: '/actuator/health/readiness',
    method: 'GET',
    header: { 'X-WX-SERVICE': 'springboot-7j2n' }
  }).then(res => console.log('健康检查', res.statusCode, res.data))
    .catch(err => console.error('原始错误', err))
  ```
  返回 HTTP 200 且 `status=UP` 后再检查超级管理员切换。域名直连返回 503 不等同于 SDK 失败，必须分别排查域名路由和云托管调用链路；控制台显示“服务正常”只说明实例状态，不等于 Java 接口已验证。
- 待结算、下单请求和通知缓存按后端、环境及服务隔离；联系人本机资料共用。云托管未取得当前服务通知配置前按关闭处理，不沿用云函数模板或 grant。
- Java 下单使用稳定 `requestId`，结果未知时按原内容重试并沿用原授权；修改内容需重新进入结算，先核实是否已下单。已有商品保存携带 `version`，过期提示刷新。原云函数忽略这两个字段，不因此获得 Java 的幂等和版本保护。
- 新分享链接带 `backend/backendScope`，Java 通知带云托管来源。无来源标记但携带记录 ID 的旧外部链接默认属于云函数，来源不匹配只提示并阻断，不自动切换或查询另一套库。无 ID、无来源标记的普通页面入口不误判为旧库链接。
- **两套订单、库存、角色、消息和授权记录不同步。** 改回 `cloudfunction` 只是重新访问原云数据库，不会把 MySQL 测试数据带回；本次不做存量迁移、双写或生产回滚。
- 云托管业务容器必须关闭公网入口，仅接受微信云托管调用链路访问；否则自填身份头可绕过鉴权。这里的平台调用链路与开发管理中的独立“微信网关”产品无关，无需开通后者。真实通知还需开放接口服务及订阅发送权限，并在修改权限后创建新服务版本。

### 新的商家上线流程

```text
提交入驻申请
→ 平台电话联系
→ 设置待线下付款
→ 平台确认线下收款
→ 管理员最终审核
→ 创建店铺并授予商家权限
→ 店铺上线
```

未经审核的微信用户不能进入商家工作台，也不会在平台生成公开店铺。

## 站内消息与微信订阅消息

新版已增加统一消息系统：

- `notifications`：站内消息
- `notification_deliveries`：站内及微信消息发送记录
- `notification_preferences`：用户订阅授权汇总
- `notification_grants`：购买者每笔订单明确确认产生的单次授权凭证
- `notification_templates`：统一微信订阅消息模板配置

订单、商家入驻、付款、审核和店铺暂停等业务共用一个微信模板：`SHARED_BUSINESS_NOTICE`。

### 配置统一微信订阅模板

1. 在微信公众平台为当前小程序选择一个订阅消息模板。
2. 模板最好包含四个通用字段：通知类型、当前状态、通知时间、通知内容。
3. 复制模板ID。
4. 使用平台管理员进入“我的 → 平台管理后台 → 消息模板配置”。
5. 填入模板ID和实际关键词编号，例如 `thing1`、`phrase2`、`time3`、`thing4`。
6. 原云函数开发调试阶段可选择“开发版”；Java 测试库默认关闭且为“体验版”（`trial`），确认测试范围后再开启。正式发送前核对版本和人员。
7. 开启推送并保存。

即使模板未配置或用户拒绝订阅，站内消息仍然正常生成。用户可在“我的 → 消息通知”查看。

### 当前微信通知策略

当前只有购买者使用微信一次性订阅消息：

- 购买者提交订单时弹出微信订阅授权卡片；
- 每笔订单只选择一个节点发送微信通知；
- 平台管理员可以选择“商家接单时通知”或“商品送达时通知”；
- 商家新订单、申请进度和平台审批暂时只产生站内消息；
- 无论用户是否同意微信授权，全部业务状态都会保存在站内消息中心。

商家收到新订单后，可在“我的 → 消息通知”或商家工作台未读红点中查看。购买者和商家使用同一个微信测试时，新订单站内信和购买者微信通知都会进入同一个账号，但只有选定的购买者节点会调用微信订阅推送。
