# 宿舍补给站 MVP

面向大学宿舍场景的学生零食小店微信小程序。学生通过商家分享卡片直达店铺，或搜索商家告知的店铺名称；线上提交订单，商品送达后双方线下付款。

## 已实现功能

### 学生端

- 按店铺名称搜索
- 分享卡片直达指定店铺
- 浏览分类、商品、价格和实时库存
- 购物车与起送金额校验
- 填写联系人、手机号、送达位置和备注
- 提交无需在线支付的订单
- 查看订单状态、取消待接单订单、确认收货

### 商家端

- 创建和编辑店铺
- 设置店名、公告、营业时间、起送金额及配送费
- 商品分类、价格、库存、上下架管理
- 开始营业/打烊
- 接单、拒单、开始配送、确认送达及完成订单
- 今日订单、成交额、待接单和低库存数据
- 分享店铺卡片给同学

## 运行方式

### 直接体验（默认）

项目默认使用本机缓存作为演示数据，不需要配置云环境即可在微信开发者工具中运行。首次打开会生成3家演示店铺和示例商品。

1. 使用微信开发者工具打开项目根目录。
2. 编译并进入“找店”页。
3. 搜索“阿豪”或直接点击演示店铺。
4. 可在“我的 → 我要开店”体验完整商家流程。
5. “我的 → 重置本机体验数据”可恢复初始状态。

### 启用云开发

1. 当前项目已配置云环境 `smooth-kiwi-d3gjwm74v84784b65`。
2. `miniprogram/app.js` 中的 `globalData.useCloud` 已设为 `true`。
3. 确认微信开发者工具当前选择的是同一个云环境。
4. 上传并部署 `cloudfunctions/snacksApi`，选择“云端安装依赖”。
5. 在云开发控制台创建以下集合，或调用云函数的 `initCollections` 操作：
   - `stores`
   - `products`
   - `orders`
6. 数据读写均通过云函数执行，数据库权限建议设置为禁止小程序端直接读写。

> 云端模式不会自动写入演示商家。首次进入后请从“我的 → 我要开店”创建店铺和商品。

## 项目结构

- `miniprogram/pages/home`：店铺搜索首页
- `miniprogram/pages/store`：店铺与购物车
- `miniprogram/pages/checkout`：确认订单
- `miniprogram/pages/orders`、`pages/order`：用户订单
- `miniprogram/pages/merchant*`：商家工作台
- `miniprogram/utils/api.js`：本地演示数据与云函数适配层
- `cloudfunctions/snacksApi`：云端业务接口
- `docs/product-design.md`：整体产品设计方案

## MVP说明

当前版本不接入在线支付，订单金额仅用于双方交付时线下结算。正式上线前仍需确认小程序主体、服务类目、食品经营资质、学校管理规定、隐私政策和商家审核流程。

## 商家审批与平台管理员初始化

最新版已启用角色、商家申请、线下付款登记和平台审核流程。部署新版云函数后会自动创建：

- `users`
- `platform_users`
- `merchant_applications`
- `merchant_payments`
- `audit_logs`
- `system_dictionaries`：角色、状态、操作等固定枚举的中文说明
- `system_collection_schemas`：每个数据库集合和字段的中文说明

### 初始化第一个超级管理员

1. 重新部署 `cloudfunctions/snacksApi` 并编译小程序。
2. 用开发者自己的微信进入“我的”。
3. 点击“复制我的身份ID”。
4. 在云开发控制台的 `platform_users` 集合手工新增一条记录：

```json
{
  "openid": "粘贴开发者自己的身份ID",
  "role": "SUPER_ADMIN",
  "roleLabel": "超级管理员",
  "displayName": "平台负责人",
  "phone": "",
  "status": "ACTIVE",
  "statusLabel": "正常",
  "createdAt": 1792684800000,
  "updatedAt": 1792684800000
}
```

`createdAt` 和 `updatedAt` 可填写当前毫秒时间戳。保存后重新进入“我的”，即可看到“平台管理后台”。

### 新的商家上线流程

```text
提交入驻申请
→ 平台电话联系
→ 设置待线下付款
→ 平台确认线下收款
→ 管理员最终审核
→ 创建店铺并授予商家权限
→ 店铺上线
```

未经审核的微信用户不能进入商家工作台，也不会在平台生成公开店铺。

## 站内消息与微信订阅消息

新版已增加统一消息系统：

- `notifications`：站内消息
- `notification_deliveries`：站内及微信消息发送记录
- `notification_preferences`：用户订阅授权汇总
- `notification_grants`：购买者每笔订单明确确认产生的单次授权凭证
- `notification_templates`：统一微信订阅消息模板配置

订单、商家入驻、付款、审核和店铺暂停等业务共用一个微信模板：`SHARED_BUSINESS_NOTICE`。

### 配置统一微信订阅模板

1. 在微信公众平台为当前小程序选择一个订阅消息模板。
2. 模板最好包含四个通用字段：通知类型、当前状态、通知时间、通知内容。
3. 复制模板ID。
4. 使用平台管理员进入“我的 → 平台管理后台 → 消息模板配置”。
5. 填入模板ID和实际关键词编号，例如 `thing1`、`phrase2`、`time3`、`thing4`。
6. 开发调试阶段选择“开发版”，正式发布后改为“正式版”。
7. 开启推送并保存。

即使模板未配置或用户拒绝订阅，站内消息仍然正常生成。用户可在“我的 → 消息通知”查看。

### 当前微信通知策略

当前只有购买者使用微信一次性订阅消息：

- 购买者提交订单时弹出微信订阅授权卡片；
- 每笔订单只选择一个节点发送微信通知；
- 平台管理员可以选择“商家接单时通知”或“商品送达时通知”；
- 商家新订单、申请进度和平台审批暂时只产生站内消息；
- 无论用户是否同意微信授权，全部业务状态都会保存在站内消息中心。

商家收到新订单后，可在“我的 → 消息通知”或商家工作台未读红点中查看。购买者和商家使用同一个微信测试时，新订单站内信和购买者微信通知都会进入同一个账号，但只有选定的购买者节点会调用微信订阅推送。
