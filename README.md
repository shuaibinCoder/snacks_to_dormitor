# 宿舍补给站 MVP

面向大学宿舍场景的学生零食小店微信小程序。学生通过商家分享卡片直达店铺，或搜索商家告知的店铺名称；线上提交订单，商品送达后双方线下付款。

## 已实现功能

### 学生端

- 按店铺名称搜索
- 分享卡片直达指定店铺
- 浏览分类、商品、价格和实时库存
- 购物车与起送金额校验
- 填写联系人、手机号、送达位置和备注
- 提交无需在线支付的订单
- 查看订单状态、取消待接单订单、确认收货

### 商家端

- 创建和编辑店铺
- 设置店名、公告、营业时间、起送金额及配送费
- 商品分类、价格、库存、上下架管理
- 开始营业/打烊
- 接单、拒单、开始配送、确认送达及完成订单
- 今日订单、成交额、待接单和低库存数据
- 分享店铺卡片给同学

## 运行方式

### 本机演示（需显式开启）

当前默认使用原云函数。若只体验本机演示，在 `miniprogram/app.js` 中将 `globalData.useCloud` 改为 `false` 后重新编译/启动；首次生成3家演示店铺和示例商品，演示缓存不会迁入远端数据库。

1. 使用微信开发者工具打开项目根目录。
2. 编译并进入“找店”页。
3. 搜索“阿豪”或直接点击演示店铺。
4. 可在“我的 → 我要开店”体验完整商家流程。
5. “我的 → 重置本机体验数据”可恢复初始状态。

### 原云函数（当前默认）

1. 当前项目已配置云环境 `smooth-kiwi-d3gjwm74v84784b65`。
2. `miniprogram/app.js` 中 `globalData.useCloud=true`、`backendProvider='cloudfunction'`。
3. 确认微信开发者工具当前选择的是同一个云环境。
4. 上传并部署 `cloudfunctions/snacksApi`，选择“云端安装依赖”。
5. 在云开发控制台创建以下集合，或调用云函数的 `initCollections` 操作：
   - `stores`
   - `products`
   - `orders`
6. 数据读写均通过云函数执行，数据库权限建议设置为禁止小程序端直接读写。

> 云端模式不会自动写入演示商家。首次进入后从“我的 → 我要开店”提交申请，完成下方平台联系、收款及审核后才能管理店铺和商品。

### Java 云托管（独立测试后端）

Java 项目位于 `/Users/shuaibin/IdeaProjects/snacks_to_dormitor_end`，使用 Java 11 / Spring Boot / MyBatis / MySQL，独立实现原云函数的 45 个 action。原 `cloudfunctions/` 保留且不改动。Java 自动建表、迁移和启动数据初始化已默认关闭，部署前需人工准备表结构、首位管理员、可信网关和微信接口权限。本项目 `miniprogram/app.js` 保持默认云开发：

```js
useCloud: true,
backendProvider: 'cloudfunction',
cloudRun: {
  env: 'prod-d0gs4er2552d66779',
  service: '', // 确认后可固定填写，也可由超级管理员在测试面板中输入。
  path: '/api/snacks'
}
```

- 入口：超级管理员进入“我的 → 平台管理后台 → 后端测试切换”，填写服务名后点击“云托管 · Java”或“云开发 · 原云函数”。服务名来自云托管控制台的服务列表，不是公网域名。
- 面板显示当前后端、云托管环境和服务名，仅远端超级管理员可操作；每次切换都会重新验证当前和目标后端的同一账号均为 `SUPER_ADMIN`，不会把旧库权限复制到 MySQL。目标连接、初始化、身份或模板检查失败时不切换。
- 切换仅影响当前设备的本次运行，不保存选择到本地存储、不改变其他用户后端；冷启动恢复代码默认 `cloudfunction`。普通用户和本机演示模式没有切换入口。服务名输入同样只保留到本次运行结束，确认后可写入上方代码配置。
- 切换前确认未保存编辑会丢失；已有请求未结束时拒绝切换，检查期间阻止新业务请求。成功后重建页面栈、重新获取身份和当前后端通知配置、清除旧角标；两套待结算缓存分别保留，旧请求不转发新后端。页面重载失败恢复原配置。
- 切换后目标服务若停机，可完全退出并冷启动恢复默认后端；这不是自动故障回退。
- 原 `globalData.env` 继续用于云函数和商品图片云存储，不能改成云托管环境；MySQL 只存云文件 ID。
- 初始化和业务统一经过 `utils/api.js`。云托管使用 `wx.cloud.callContainer`、独立环境和 `X-WX-SERVICE`，不由客户端发送身份头。
- 云托管环境/服务缺失、不支持 API、网络错误、身份拒绝和初始化失败均明确提示，不自动重试写请求，也不回退到云函数或本地数据。
- 待结算、下单请求和通知缓存按后端、环境及服务隔离；联系人本机资料共用。云托管未取得当前服务通知配置前按关闭处理，不沿用云函数模板或 grant。
- Java 下单使用稳定 `requestId`，结果未知时按原内容重试并沿用原授权；修改内容需重新进入结算，先核实是否已下单。已有商品保存携带 `version`，过期提示刷新。原云函数忽略这两个字段，不因此获得 Java 的幂等和版本保护。
- 新分享链接带 `backend/backendScope`，Java 通知带云托管来源。旧外部链接默认属于云函数，来源不匹配只提示并阻断，不自动切换或查询另一套库。
- **两套订单、库存、角色、消息和授权记录不同步。** 改回 `cloudfunction` 只是重新访问原云数据库，不会把 MySQL 测试数据带回；本次不做存量迁移、双写或生产回滚。
- 云托管业务容器必须关闭公网入口，仅信任微信网关访问；否则自填身份头可绕过鉴权。真实通知还需开放接口服务及订阅发送权限，并在修改权限后创建新服务版本。

### 初始化第一个超级管理员（原云函数）

以下集合 JSON 仅用于原云数据库。Java 测试库需按 Java 项目 README 中的显式 SQL 单独初始化，不能把此 JSON 直接用于 MySQL。

1. 重新部署 `cloudfunctions/snacksApi` 并编译小程序。
2. 用开发者自己的微信进入“我的”。
3. 点击“复制我的身份ID”。
4. 在云开发控制台的 `platform_users` 集合手工新增一条记录：

```json
{
  "openid": "粘贴开发者自己的身份ID",
  "role": "SUPER_ADMIN",
  "roleLabel": "超级管理员",
  "displayName": "平台负责人",
  "phone": "",
  "status": "ACTIVE",
  "statusLabel": "正常",
  "createdAt": 1792684800000,
  "updatedAt": 1792684800000
}
```

`createdAt` 和 `updatedAt` 可填写当前毫秒时间戳。保存后重新进入“我的”，即可看到“平台管理后台”。

### 新的商家上线流程

```text
提交入驻申请
→ 平台电话联系
→ 设置待线下付款
→ 平台确认线下收款
→ 管理员最终审核
→ 创建店铺并授予商家权限
→ 店铺上线
```

未经审核的微信用户不能进入商家工作台，也不会在平台生成公开店铺。

## 站内消息与微信订阅消息

新版已增加统一消息系统：

- `notifications`：站内消息
- `notification_deliveries`：站内及微信消息发送记录
- `notification_preferences`：用户订阅授权汇总
- `notification_grants`：购买者每笔订单明确确认产生的单次授权凭证
- `notification_templates`：统一微信订阅消息模板配置

订单、商家入驻、付款、审核和店铺暂停等业务共用一个微信模板：`SHARED_BUSINESS_NOTICE`。

### 配置统一微信订阅模板

1. 在微信公众平台为当前小程序选择一个订阅消息模板。
2. 模板最好包含四个通用字段：通知类型、当前状态、通知时间、通知内容。
3. 复制模板ID。
4. 使用平台管理员进入“我的 → 平台管理后台 → 消息模板配置”。
5. 填入模板ID和实际关键词编号，例如 `thing1`、`phrase2`、`time3`、`thing4`。
6. 原云函数开发调试阶段可选择“开发版”；Java 测试库默认关闭且为“体验版”（`trial`），确认测试范围后再开启。正式发送前核对版本和人员。
7. 开启推送并保存。

即使模板未配置或用户拒绝订阅，站内消息仍然正常生成。用户可在“我的 → 消息通知”查看。

### 当前微信通知策略

当前只有购买者使用微信一次性订阅消息：

- 购买者提交订单时弹出微信订阅授权卡片；
- 每笔订单只选择一个节点发送微信通知；
- 平台管理员可以选择“商家接单时通知”或“商品送达时通知”；
- 商家新订单、申请进度和平台审批暂时只产生站内消息；
- 无论用户是否同意微信授权，全部业务状态都会保存在站内消息中心。

商家收到新订单后，可在“我的 → 消息通知”或商家工作台未读红点中查看。购买者和商家使用同一个微信测试时，新订单站内信和购买者微信通知都会进入同一个账号，但只有选定的购买者节点会调用微信订阅推送。
